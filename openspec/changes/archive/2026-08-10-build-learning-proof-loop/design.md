## Context

当前系统已经分别保存同题提交成长、Coach 问答、推荐行动和后续换题提交，但学生与教师看到的是四组分散能力。结果是学生通过后只看到一次结果，教师也只能看到问题人数，无法回答“学生在哪次真正修正、能否说清、能否在另一题再次做到”。

本次改动以学生和教师共同可见的三个阶段为唯一产品合同：

```text
关键修改 → 学生说明 → 换题验证
```

这三个阶段必须指向真实提交、问题变化或保存的回答。没有对应证据时只显示“尚未”，不得展示低可信度结论，也不得用新的 AI 文案代替缺失事实。

## Goals / Non-Goals

**Goals:**

- 用一个后端聚合对象向学生端和教师端返回完全相同的学习证明状态。
- 从现有单题成长投影中选择真正改变评测或问题集合的关键修改，并保留前后提交入口。
- 让学生在当前题内回答一条固定修正说明，答案绑定具体提交并幂等保存。
- 只在存在真实同作业、同知识关系的未做题时给出换题入口，并用后续正式提交回填验证状态。
- 让教师在题目页按“曾未通过、已修正、已说明、换题已验证”筛选学生并下钻到同一证据。

**Non-Goals:**

- 不新增成长分数、理解分数、置信度或教师教学决策。
- 不重新实现提交比较、问题生命周期或换题结果判断。
- 不把学生的一次文字回答直接等同于已经掌握。
- 不新增数据库表或迁移；固定修正说明复用 `coach_prompts`。
- 不重做学生端现有成长图表和教师端既有问题分析结构。

## Decisions

### 1. 由统一聚合服务生成三个阶段

新增 `LearningProofService`，以学生、题目和作业范围为边界，组合 `SubmissionGrowthSummaryService`、`CoachPrompt`、`CoachAnswerQualityAnalyzer` 与 `PostAcTransferAnalyzer` 的结果。学生接口和教师聚合接口均消费该服务，不允许前端自行判定阶段。

选择这一方式是为了避免教师端再次实现一套“前后提交比较”规则。备选方案是在前端拼接成长、Coach 和推荐接口，但会导致重复请求、状态漂移和无法批量统计，因此不采用。

### 2. 关键修改只从可比较成长证据中选择

聚合服务遍历同范围成长摘要，优先选择已经恢复问题、增加通过测试点或把先前未通过变为通过的有效提交。重复无变化或不可比较提交保留在时间线中，但不能成为关键修改。输出只包含前后提交、测试点变化和恢复问题，不暴露内部选择分值。

若只有“曾未通过后通过”的判题证据，也可形成最小修正证明；若连此前失败都没有，则显示尚未观察到关键修改。

### 3. 修正说明是固定问题，不新增模型生成链

为通过或已有明确修正证据的提交创建 `LEARNING_REFLECTION` 类型 Coach 记录，固定问题要求学生说明改了哪里、为何失败并给出可验证样例或边界。创建接口幂等：同一提交已有该类型记录时返回原记录。

回答保存后复用 `CoachAnswerQualityAnalyzer` 检查是否包含可核验内容。界面只区分“尚未说明、已提交说明、说明可核验”，分析结果只作为说明反馈，不宣称学生已经理解。

### 4. 换题目标必须来自真实关系

目标只从同一作业的未尝试题目中选择，并要求与来源题存在知识点交集；找不到时返回“尚未安排换题验证”，不得选任意新题。后续同能力题的正式提交由现有 `PostAcTransferAnalyzer` 判断，只有出现真实通过证据时才显示“换题已验证”。

首版不自动生成新题，也不跨作业猜测能力关系。这样会减少可推荐目标，但能够保证每个入口可追溯。

### 5. 教师页保留问题分析主体，只增加一行阶段筛选

教师题目页顶部状态栏展示四个直接人数，点击后筛选已有学生列表；点击某个规范问题时恢复现有问题筛选。学生行只增加一个短状态，详情页展示与学生端相同的三个阶段。

不新增大面积介绍、独立概览页或装饰性图表，以免把正文推到首屏下方。

## Risks / Trade-offs

- `[固定问题可能得到敷衍回答]` → 只把回答标记为已提交；只有检测到样例、边界或具体修改证据时才显示可核验，仍不等同掌握。
- `[知识点字段不完整导致没有换题]` → 诚实显示尚未安排，后续可通过标准库关系扩展目标选择，不在本次猜测标签。
- `[教师批量聚合可能产生额外查询]` → 按作业题目一次加载提交与学生，再分组构建状态；禁止逐学生调用控制器接口。
- `[旧 Coach 记录与新说明混淆]` → 使用独立 `promptType` 过滤，不修改原有多轮 Coach 行为。
- `[一次通过学生没有修正过程]` → 计入提交事实但不伪造修正；教师阶段栏的“曾未通过”与“已修正”保持不同集合。

## Migration Plan

1. 新增 DTO、聚合服务和接口，不修改已有接口字段。
2. 学生题目页和教师题目页在新接口失败时保留原页面，不阻塞提交与原分析。
3. 复用现有表，无数据库迁移和数据回填；历史 Coach 记录不会被识别为修正说明。
4. 验证完成后归档 OpenSpec 变更；若需要回滚，只移除新路由与视图即可，原数据仍可由现有 Coach 能力读取。

## Open Questions

- 后续是否允许教师为某一知识点指定换题目标，应基于本轮真实使用数据再决定；本次不加入配置入口。
