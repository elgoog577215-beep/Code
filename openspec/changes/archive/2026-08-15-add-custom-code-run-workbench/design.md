## Context

正式提交会按题目测试点执行并写入学习证据，随后触发 AI 反馈。自定义运行只服务学生修改代码时的即时验证，不能复用 `Submission` 生命周期，也不能暴露隐藏测试点。执行端点同时面向匿名公开练习，因此必须在进入进程执行前完成访问、大小、频率和并发约束。

## Goals / Non-Goals

**Goals:**

- 单组 `stdin` 运行当前 Python/C++17 代码并返回 `stdout/stderr/status/time`。
- 运行结果与正式提交完全隔离。
- 使用题目定义的时间和内存限制，不信任客户端资源参数。
- 有界捕获 stdout/stderr，保留空白并明确标识截断。
- 桌面、移动和中英文模式下提供可重复运行的内联工作台。

**Non-Goals:**

- 不做断点、单步、变量监视、交互式终端或多组自定义用例。
- 不比较自定义输出与期望输出。
- 不保存调试历史，不向教师或 AI 提供运行内容。
- 不安装或替换 C++17/Docker 执行环境。

## Decisions

### 独立运行资源而不是特殊提交

使用 `POST /api/code-runs` 返回无 ID 的即时结果。服务只读取题目限制并调用 `CodeExecutor`，不访问测试点或提交仓储，从结构上防止自定义运行进入提交统计和 AI 流程。

### 服务端确定身份与资源限制

请求只包含 `problemId`、可选 `assignmentId`、`languageId`、`sourceCode` 和 `stdin`。班级作业通过学生令牌解析身份并校验班级与题目归属；公开练习允许匿名。时间、内存和输出上限均由服务端确定。

### 有界流捕获

执行器使用 UTF-8 字节流捕获并保留换行。达到 stdout/stderr 上限后继续排空流但不继续积累内容，结果用独立截断标记通知界面，避免无限输出占满 JVM 内存。

### 单节点内存保护

按已认证学生 ID、否则按请求远端 IP 建立一分钟窗口；同一键只允许一个在途执行，并使用全局信号量限制并发。限制存于内存，适配当前单节点校内部署。

### 内联运行状态

输入与最近结果位于编辑器下方。载入样例只复制第一个公开样例输入；修改代码、语言或输入后保留结果但标记过期。运行与正式提交互斥，运行完成不刷新历史或触发 AI 请求。

## Risks / Trade-offs

- 匿名公开运行会增加资源消耗。通过 IP 限流、全局并发、输入输出上限和紧急开关收敛风险。
- 本地执行模式不能保证生产级内存隔离。正式部署仍要求 Docker；本机仅用于开发。
- 代理后的匿名请求可能共享远端 IP。当前单节点部署接受该限制，多实例或复杂代理环境后续接入共享限流与可信代理配置。
