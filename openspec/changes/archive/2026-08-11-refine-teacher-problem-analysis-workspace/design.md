## Context

题目分析页目前同时读取作业题目摘要和学习证明聚合。题目摘要的 `students` 只由有提交的学生分组生成，因此在册但未提交的学生完全缺席；前端正文又使用接近视口高度的最小高度，数据少时形成大面积无意义空白。页面顶部的四个题目指标与四个学习阶段权重相同，零数据状态尤其像八个并列统计块。

本轮属于教师端问题页的局部重构，沿用现有教师壳层、色彩变量、路由、学习证明服务和学生证据详情，不改变学生端主体。

## Goals / Non-Goals

**Goals:**

- 教师在题目页第一眼看到当前题对象、班级参与情况和学习证据进展。
- 学生正文覆盖全班在册名单，未提交与已提交状态同一处呈现。
- 问题证据存在时可筛选对应学生，不存在时不保留空白问题栏。
- 页面在桌面和窄屏下都保持清楚、紧凑，并同步中英文。

**Non-Goals:**

- 不新增抽象分析维度、图表、自动教学建议或虚构样例数据。
- 不修改提交人数、一次通过、最终通过、有效修改和学习阶段的既有统计口径。
- 不重排学生端页面或教师端其他层级页面。

## Decisions

### 1. 题目学生摘要以全班在册名单为显示集合

`ClassroomService` 继续使用合法提交者集合计算提交、通过和有效修改人数，但构建 `ProblemSummary.students` 时遍历全班在册学生。没有提交的学生复用现有学生摘要结构，返回 `attemptCount=0`、`latestSubmissionId=null`、`latestVerdict=暂无`，不创建成长状态或证据。

选择该方案而不是前端再请求名单并合并，是因为班级身份、分母和排序应由后端统一，避免前端重复定义学生口径。

### 2. 页面阅读顺序固定为对象、过程、正文

页面保留对象路径与标题；题目四项基础状态继续位于标题同行，学习证明阶段改成连续的紧凑过程条。正文默认展示全班学生，不再自动选中第一条问题；教师点击问题或学习阶段后才进入对应筛选。

选择默认全班而不是默认第一条问题，是因为教师进入题目页首先需要知道谁提交、谁未提交，再决定是否按问题下钻。

### 3. 问题和学生使用条件式主从布局

存在规范问题证据时，桌面使用窄问题栏与宽学生区；不存在时只渲染学生区。移除正文强制视口最小高度，让容器高度跟随真实内容。窄屏按“过程 → 问题 → 学生”顺序纵向排列，筛选控件允许横向滚动或换行。

### 4. 未提交学生是客观状态，不是空状态

未提交学生显示姓名、学号和“未提交”，提交数与有效修改使用 0 或短横线，不显示当前问题，也不提供跳转到不存在证据的详情页。只有班级本身无在册学生或筛选确实无匹配学生时才显示空状态。

## Risks / Trade-offs

- [全班名单增加行数] → 学生列表保持行式布局，后续数据规模较大时再增加分页或虚拟化，本轮不提前引入复杂组件。
- [旧测试假设只返回提交者] → 增加无提交与部分提交用例，并保持提交/通过计数断言不变。
- [移动端筛选过宽] → 学习阶段使用可滚动的连续控件，问题统计改为紧凑两行，不把桌面网格硬压到窄屏。
- [无提交学生被误认为可分析] → 后端不生成学习证明，前端不创建详情链接，并使用明确的未提交状态。

## Migration Plan

无数据库迁移。后端 DTO 结构不变，只扩展 `ProblemSummary.students` 的集合范围；前端可与旧后端兼容，旧后端只会继续少显示未提交学生。回滚时恢复列表构建范围和局部组件/CSS 即可。

## Open Questions

无。学生数量达到需要分页的规模时另行依据真实班级数据设计。
