## Context

当前教师正式页面已经只需要班级完成情况、作业完成情况、题目问题人数和学生逐次变化，但班级页仍并发获取每个作业概览后在浏览器中合并人数。作业概览服务同时运行十余个扩展分析器，且教师问题生命周期与学生单题成长投影分别实现了“有效提交”判断。学生首页只展示第一条推荐，但推荐服务会先计算并排序迁移、自解释、AI 依赖、掌握度和教学动作等策略。

这造成三个直接偏差：同一个学生或问题可能在两端得到不同变化状态；抽象策略可能覆盖最近未完成任务；前端必须理解统计分母才能拼出班级基础数字。

## Goals / Non-Goals

**Goals:**

- 后端直接提供班级层基础事实，保持学生分母稳定。
- 教师问题统计和学生单题成长复用同一份有效修改与问题变化投影。
- 学生下一步行动稳定收敛为一个可执行对象。
- AI 诊断、证据版本和教师校正继续完整保存并可下钻。

**Non-Goals:**

- 不删除 AI 质量、实验评测、推荐效果等内部观测接口。
- 不在本次重写完整诊断模型调用或标准库挂接链路。
- 不增加成长分数、可信度等级、能力雷达或新的抽象标签。

## Decisions

### 1. 班级基础统计使用独立轻量聚合接口

新增 `GET /api/teacher/classes/{classGroupId}/learning-overview`。服务一次读取班级、作业、任务、学生和提交，返回班级四个基础数字及作业行。作业行只包含教师进入作业前需要的标题、状态、题数、已提交人数和完成必做题人数。

没有选择继续由前端聚合，因为这会让浏览器承担去重、分母和失败降级规则，也会产生按作业数量增长的请求数。

### 2. `SubmissionGrowthSummaryService` 是有效修改与问题变化的唯一事实源

教师证据聚合不再自行比较相邻原始提交，而是读取单题成长投影的 `effectiveAttempt` 和 `issueSignals`。教师的“反复出现”来自有效提交上的 `PERSISTED/RECURRED`；“后来解决”来自 `RECOVERED`；最新未解决状态来自最后一个有效提交。

诊断事实仍负责问题身份、知识路径和证据引用，成长投影负责前后变化。两者职责不重叠。

### 3. 教师题目学生状态只保留可直接核验的判断

题目学生摘要的关注状态由最新判题、有效修改次数和成长状态决定。AI 反馈影响、跨题迁移、自解释、AI 依赖和掌握度不再参与正式题目列表排序。旧扩展字段暂时保留兼容，但正式页面不读取。

### 4. 学生推荐服务只产生一个当前行动

行动顺序固定为：

```text
存在最近未通过题目 → 继续处理该题
没有未通过题目且存在未做题 → 开始一题新题
没有安全题目入口 → 复盘最近一次提交
```

推荐仍保存 token、来源问题和后续提交事件，便于验证行动是否执行；但不再用高级分析器重新覆盖主行动。

## Risks / Trade-offs

- [旧测试依赖多策略推荐] → 更新为验证一个主行动及其证据事件；高级分析器测试保留为内部模块测试。
- [历史页面仍读取旧作业概览字段] → 本次不删除字段，只让正式教师分析和学生首页改用精简合同。
- [部分提交缺少成长投影依赖的正式分析] → 原始判题和提交仍展示；不生成反复或解决结论。
- [班级内同一题出现在多个作业] → 班级概览只聚合作业完成事实，不在班级层猜测题目问题归属；问题分析继续在作业题目范围完成。

## Migration Plan

1. 先上线新班级概览接口和前端读取，保留旧作业概览接口。
2. 教师证据聚合切换到共享成长投影，运行生命周期回归测试。
3. 学生推荐收敛为单行动，保留原推荐事件表和历史 token。
4. 若需回滚，前端可恢复按作业读取；数据库无需迁移或回退。

## Open Questions

无。本次只收敛正式主流程，扩展观测能力是否进一步清理留到真实使用数据出现后再决定。
