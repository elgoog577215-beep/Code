## Why

系统已经具备作业级提交列表、题目内提交时间线、单题成长仪表盘、问题生命周期投影和两次提交代码差异接口，但这些能力分散在不同页面与弹层中。学生看到的导航名称只是“提交”，题目历史仅在已有记录时出现，成长仪表盘藏在结果弹层的第二层；现有两次提交对比接口也没有前端入口。结果是功能在代码中存在，却没有形成用户能够发现、理解和操作的完整体验。

本变更把分散能力统一为“历史记录 → 选择版本 → 查看变化 → 返回继续修改”的闭环，使学生既能快速回看一次提交，也能主动比较任意两次同题提交，并理解代码、评测和问题证据分别发生了什么变化。

## What Changes

- 将学生作业导航中的模糊“提交”入口明确为“提交与成长”，保留作业级全部记录、筛选、分页和详情回看能力。
- 为没有历史记录的题目提供固定但轻量的历史入口与空状态；有记录时显示最近提交摘要和“查看全部”入口，不让历史能力依赖条件渲染才能被发现。
- 新增独立的双版本对比工作台，允许学生从同一道题的历史中选择基线版本和目标版本，并支持交换、恢复系统推荐基线和从时间线快速替换版本。
- 对比工作台统一展示结果变化、测试点变化、问题生命周期变化、知识路径变化和逐行代码差异；缺少可靠诊断证据时诚实降级，不把未返回的问题显示为已解决。
- 复用现有成长摘要、历史接口和 `/api/submissions/compare`，扩展前端 API 类型与必要的结构化比较字段；不新增第二套成长算法，不新增数据表。
- 将题目页成长仪表盘保留为轻量趋势与当前提交摘要，深度历史查看和任意版本对比进入独立工作台，避免破坏“题目—代码—提交反馈”的主流程。
- 同步维护中英文文案、键盘与屏幕阅读器语义、移动端单列对比模式、桌面端并排模式和明暗主题。

## Capabilities

### New Capabilities

- `student-submission-comparison-experience`: 定义历史入口可发现性、双版本选择、结构化成长对比、代码差异、证据降级和响应式交互。

### Modified Capabilities

- `student-submission-history-continuity`: 将历史提交从条件性题目区块和独立列表统一为可发现、可回看、可进入对比的连续体验。

## Impact

- 前端：学生作业导航、作业级提交页、题目页历史摘要、成长仪表盘、路由、共享 API 类型、新的提交对比工作台及中英文文案。
- 后端：优先复用现有比较服务；如当前响应不足以支撑结构化问题变化，则兼容性扩展比较响应并复用 `SubmissionGrowthSummaryService` 与问题生命周期事实。
- API：保留 `/api/submissions/compare` 地址和已有字段，新增字段必须向后兼容；比较权限继续限制为同一学生可访问的同题提交。
- 数据库：不新增迁移，不创建第二套成长事实或比较快照。
- 验证：后端比较权限与结构化响应测试、前端类型检查与构建、桌面/移动/中英文/明暗主题 browser smoke。
