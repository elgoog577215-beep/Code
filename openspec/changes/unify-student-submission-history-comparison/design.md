## Context

当前产品已经存在三条相关链路：

1. 作业级提交页提供全部提交、筛选和回看；
2. 题目页读取同一学生、作业和题目范围内的历史摘要，并展示时间线与成长仪表盘；
3. 后端比较服务支持同题两次提交的代码 Diff、判题变化和文本摘要。

缺口主要在信息架构和数据拼装，而不是底层数据采集。历史入口命名不清晰且有条件渲染，成长分析被封装在提交结果弹层内，比较接口没有前端消费者。与此同时，现有学生主流程要求每页突出一个主动作，因此不能简单把更多历史图表永久堆入题目页。

## Goals / Non-Goals

**Goals：**

- 学生在作业页和题目页都能稳定发现历史能力。
- 学生可以选择任意两次属于自己的同题、同上下文提交进行比较。
- 一次对比明确回答：结果是否改善、哪些问题变化、代码改了什么、比较证据是否完整。
- 自动成长基线与用户手动比较并存，且明确区分。
- 深度分析离开题目主操作区，不增加提交前的认知负担。
- 所有状态均可通过稳定字段、文本和图标理解，不只依赖颜色。

**Non-Goals：**

- 不做学生之间、班级之间的成长排名或横向比较。
- 不在本变更中建设跨题综合能力画像首页。
- 不使用代码改动行数直接判定学习进步。
- 不重新训练或新增 AI Agent，不重新定义现有成长状态算法。
- 不新增成长分数，不把不可比较数据补写为推测结论。
- 不重做教师端分析工作台；教师复用可作为后续变更。

## Information Architecture

```text
学生作业
├─ 题目
├─ 排名
└─ 提交与成长
   ├─ 全部提交
   ├─ 按题目查看轨迹
   └─ 选择两次提交进行对比

题目页
├─ 题目与代码（主流程）
├─ 最近结果与修正建议
└─ 历史摘要（次级入口）
   ├─ 打开一次历史提交
   ├─ 查看本题完整成长
   └─ 对比两个版本
```

桌面端对比工作台采用三段结构：

```text
[题目与上下文] [基线版本选择器] ⇄ [目标版本选择器]

[结果变化] [测试点变化] [问题变化] [证据完整性]

[成长证据/知识路径] | [代码 Diff]
```

移动端使用单列顺序：版本选择 → 核心结论 → 问题变化 → 代码差异；基线与目标代码不做强制左右并排，改为统一 Diff 流或“基线/目标”切换。

## Decisions

### 1. 使用独立对比路由，不把完整对比塞进结果弹层

新增形如 `/app/student/assignments/:assignmentId/problems/:problemId/compare?leftId=&rightId=` 的可分享内部路由。题目结果弹层继续服务“这一次先改什么”，历史与对比工作台服务“前后发生了什么”。

这样可以保留学生主流程的一主动作原则，也允许浏览器返回、刷新恢复、从提交列表深链进入和移动端完整滚动。

### 2. “自动成长基线”和“手动对比版本”是两种不同语义

现有 `growthSummary.comparisonSubmissionId` 是系统根据有效、可比较规则选择的成长基线，主要用于可靠的生命周期判断。用户手动选择的 `leftId/rightId` 用于查看两个版本的客观差异。

工作台默认使用目标提交的系统推荐基线；学生可以改选其他同题提交。改选后页面必须显示“自选对比”，不得把该组合伪装成系统成长基线，也不得重新计算并覆盖正式成长状态。

### 3. 比较响应采用分层事实，不以自然语言摘要作为主要契约

保留现有 `progressSummary`、`causeChanges` 和 `diffLines` 以兼容旧消费者，同时逐步补充结构化字段：

- `comparisonMode`: `SYSTEM_BASELINE` 或 `MANUAL`
- `comparability`: 是否可比较、完整性状态和不可比较原因
- `judgeDelta`: 前后 verdict、通过测试点、总测试点和差值
- `issueDelta`: 持续、新增、复发、未观察、恢复及不可比较问题
- `knowledgePathDelta`: 稳定知识节点及对应证据提交
- `diffStats` / `diffLines`: 代码差异

前端只翻译状态与组合展示，不从自然语言中解析计数或问题类别。

### 4. 历史列表承担版本选择，时间线承担上下文理解

作业级“提交与成长”页保留高密度列表和筛选。进入对比模式后，每行提供“设为基线”和“设为目标”，达到两个合法版本后启用“开始对比”。

题目页时间线用于快速理解顺序和状态，节点提供“查看本次”和“与当前对比”。不在每个节点堆叠多个永久按钮，使用选中态或上下文操作保持密度可控。

### 5. 版本选择必须遵守确定性约束

- 两个版本必须属于同一题目。
- 课堂作业默认还必须属于同一 `studentProfileId + assignmentId + problemId` 范围。
- 公共题库只能比较同一登录学生的无作业提交；匿名提交不进入个人成长工作台。
- 基线时间默认早于目标时间；若学生反向选择，界面提供交换并明确方向。
- 同一版本不能同时作为两侧。
- 无权访问、已删除或上下文不匹配时，后端拒绝，前端清空非法选择并给出可恢复提示。

### 6. 对比结论按证据强度逐层降级

可靠的正式诊断事实存在时，展示完整问题变化和知识路径。只有判题与测试点时，展示结果变化和代码差异，并注明“诊断证据不足”。只有源码时，仍可显示代码 Diff，但不生成进步结论。

`NOT_OBSERVED` 必须表达为“本次未再观察到”，只有满足现有恢复规则的 `RECOVERED` 才显示“已有恢复证据”。任何缺失都不得被转换成零问题。

### 7. 题目页始终显示历史入口，但保持轻量

无历史时显示一行空状态：“完成首次提交后，这里会形成历史与成长记录”。有一条记录时显示成长起点和“查看记录”；有两条及以上时显示最近节点、比较基线提示和“查看全部 / 对比版本”。

入口不因 `history.length === 0` 完全消失，但不使用大卡片抢占编辑与提交区域。

### 8. 性能采用摘要列表加按需详情

历史列表继续使用分页或增量加载；初次加载不请求每条提交的完整源码和反馈。进入工作台后并行获取：

- 当前题目历史摘要；
- 指定两次提交的比较响应；
- 必要时获取单次完整详情。

取消或切换版本时丢弃过期请求结果，避免快速选择导致左右版本错配。不为每个历史节点触发单独反馈请求。

### 9. 可访问性与国际化是验收条件

版本选择器使用明确 label，交换按钮有方向性辅助文本，对比变化同时使用文字、符号和颜色。代码 Diff 行提供“新增/删除/未变化”文本语义。所有新文案进入中英文 locale，不在 JSX 中新增硬编码中文。

## Risks / Trade-offs

- **对比页信息密度过高**：默认先显示四项核心变化，问题明细和完整 Diff 可分区折叠；移动端保持单列。
- **用户把自选对比当成正式成长结论**：显著区分“系统基线”和“自选对比”，手动组合只展示客观差异。
- **历史诊断不完整**：显示完整性状态，保留判题和源码事实，不推测问题已经解决。
- **长代码 Diff 性能下降**：虚拟化或分段渲染长 Diff，首屏优先返回统计与变化摘要。
- **已有比较服务文本存在兼容消费者**：只做向后兼容扩展，不删除原字段。
- **入口增多破坏学生主流程**：题目页只增加轻量次级入口，深度操作统一进入独立工作台。

## Migration Plan

1. 先补充共享类型和前端比较 API 客户端，保持现有页面不变。
2. 如需要，向后兼容扩展比较响应的结构化字段并补齐权限测试。
3. 建立独立比较路由和工作台，支持 URL 恢复、默认系统基线与手动选择。
4. 将作业级“提交”升级为“提交与成长”，接入版本选择和按题目轨迹入口。
5. 将题目页条件性历史面板改为始终可发现的轻量入口，并连接独立工作台。
6. 收敛结果弹层中的重复历史操作，只保留当前摘要和深度查看入口。
7. 完成双语、响应式、主题和 browser smoke 后逐步启用；回滚时可隐藏新入口，旧提交列表和结果弹层仍可独立工作。

## Open Questions

- 第一版是否只开放学生端，教师端沿用现有证据下钻；本设计建议先学生端闭环，教师复用另立变更。
- 超长 Diff 的首版采用折叠分段还是虚拟滚动，可根据现有代码编辑器依赖和真实样本性能在实现阶段确定。
