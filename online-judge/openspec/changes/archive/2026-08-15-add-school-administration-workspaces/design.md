## Context

当前 `teacher_accounts` 只有 `ADMIN/TEACHER`，`school_name` 是不可验证文本；`AdminConsolePage` 混在教师 Shell 中，平台管理员可列出所有教师并直接修改其额度。`teacher_ai_quotas` 只按教师和月份记录，没有学校总池。上一版明确“不引入学校组织层”，本变更以用户的新决策替代该边界。

## Goals / Non-Goals

**Goals:**

- 建立平台、学校、教师三级角色以及不可跨校的学校租户边界。
- 每校恰有一个当前有效校管账号，校管负责教师生命周期和额度分配。
- 平台只看学校级汇总和跨校题目审核，校管只读查看本校教学明细。
- 额度分配和使用在并发下同时满足学校池与教师额度约束。
- 以可备份、可预览、显式确认的方式清理未上线的历史教师试用数据。

**Non-Goals:**

- 不做多校区、多校管、校内协作角色、支付、BYOK、短信/邮箱找回或额度结转。
- 不允许校管修改教师教学数据，也不允许平台读取普通教师和学生明细。
- 不根据自由文本学校名自动创建或合并学校。

## Decisions

### 1. 共用认证基础设施，账号角色与入口彻底分离

保留账号表、BCrypt、数据库会话和 HttpOnly Cookie，角色改为三值。会话主体增加 `schoolId/schoolName`；登录请求携带 portal，角色不匹配不创建会话。平台、校管和教师分别使用路径角色规则和独立前端 Shell，避免管理员通过教师入口获得隐式权限。

### 2. 学校额度属于学校而非校管账号

`school_ai_quotas` 保存自然月总量，`teacher_ai_quotas` 保存教师获配额度。校管更换不影响学校额度。调整学校总量和教师分配时锁定学校月度行；教师分配总和不得超过学校总量，教师额度不得小于已用与预留。教师批准后当月额度为 0。

### 3. 学校注册码使用高熵随机值和快速哈希

注册码使用至少 128 位随机熵，数据库仅保存 SHA-256 哈希；高熵使快速哈希不存在短码离线枚举风险。创建和轮换只返回一次明文，轮换后旧码立即失效。注册接口按 IP 限流且不暴露学校枚举。

### 4. 校管教学访问使用专用只读投影

不复用教师写接口，也不提供 impersonation。`/api/school-admin/teaching/**` 只暴露 GET/导出，查询从当前校管会话取得学校 ID，再通过资源所有教师的学校归属过滤。明细查看和导出记录资源 ID，不记录学生姓名、学号、代码或密码。

### 5. 学校停用是整校安全冻结

停用事务撤销学校管理员、教师和学生会话。教师/学生认证恢复时再次检查学校为 `ACTIVE`；提交和 AI 网关也重复检查，避免已有请求绕过。历史数据保持原所有者和只读状态。

### 6. 历史清理采用扩展—清理—收紧

V6 创建学校结构和可空归属并把 bootstrap `ADMIN` 转为 `PLATFORM_ADMIN`；V7 在已验证备份与精确确认值存在时清理所有旧教师及其依赖数据，同时把已发布 `PUBLIC/SHARED` 题转交平台管理员；V8 增加角色/学校、唯一校管和额度索引约束。清理前输出计数清单，不满足门禁时不得运行生产迁移。

## Risks / Trade-offs

- [校管拥有学生敏感数据读取权] → 使用专用只读 API、学校 ID 双重校验、导出审计和无写方法设计。
- [并发额度分配超出学校池] → 锁定学校月度额度行并在同一事务内重新汇总教师获配额度。
- [自动 Flyway 启动误删历史数据] → school 启动脚本先备份并校验清理确认；迁移测试只操作隔离数据库。
- [旧前端/API 仍使用 ADMIN] → 提供一版兼容别名并在类型、导航和浏览器 smoke 中禁止旧角色继续出现。
- [深层 SPA 地址刷新 404] → 服务端统一转发 `/app/**` 到应用入口并排除静态资源和 API。

## Migration Plan

1. 在隔离数据库运行历史清理预览，核对账号、班级、提交、分析、AI 和题目数量。
2. 生成并验证可恢复备份，设置精确清理确认值后在生产副本执行 V6–V8。
3. 验证仅保留 bootstrap 平台管理员和已发布平台题，且不存在无学校校管/教师或超分额度。
4. 部署前端和后端，创建一所试点学校并交付一次性校管密码与注册码。
5. 通过完整浏览器闭环后扩到 3–5 所学校；失败时停止服务并从备份恢复。
