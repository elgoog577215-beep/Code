## Context

教师分析正式路径已经统一为班级 → 作业 → 题目 → 学生证据，基础数据来自 `ClassLearningOverview`、`AssignmentOverview`、题目学习证明和提交证据接口。当前问题不在于缺少更多指标，而在于入口层没有展示已有关键状态、窄屏布局丢失功能、行内数据机械换行，以及学生详情重复展示数据却缺少跨工作区提交切换。服务端前端路由表同时漏掉了新的学生详情路径。

## Goals / Non-Goals

**Goals:**

- 让教师从班级入口开始就能看到名册、已提交和未提交三个决策状态。
- 保证 390px 窄屏上教师头部、五个功能入口、对象路径和行内指标均可读、可点、无水平截断。
- 让题目与学生列表优先表达已提交、未提交、一次通过和最终通过等普通教师能直接理解的数据。
- 让学生详情中的当前提交在三个分类工作区中保持可见并可直接切换。
- 让教师模式成长信息紧凑呈现真实变化，不重复页头数字，不为无数据维度生成空卡。
- 使学生详情正式 URL 可直接打开和刷新。

**Non-Goals:**

- 不新增统计口径、数据库字段、AI 结论或教师决策建议。
- 不改造学生端成长仪表盘和学生做题主流程。
- 不重做教师管理页业务功能，不引入新的设计系统或图表依赖。

## Decisions

### 1. 班级入口复用现有班级学情接口

班级列表先获取班级对象，再并行读取每个班级的 `learning-overview`，以班级 ID 保存摘要。单个摘要失败时保留班级入口并退回年级信息，不让局部统计失败阻塞全页。

未选择新增聚合 API：当前班级规模有限，前端并行请求可以直接交付价值；本次不扩大后端统计契约，后续只有在班级数量造成可测性能问题时再合并接口。

### 2. 窄屏采用固定分类网格而非无提示横向滚动

390px 下全局教师头部把品牌、菜单和语言控制收在同一行；教师功能导航采用“教学分析一行 + 四个管理入口一行”的显式网格。对象路径只显示上一级和当前对象，完整层级仍保留在 DOM 和桌面端。

未选择继续横向滚动：当前滚动条被隐藏且最后入口被截断，用户无法知道还有内容。

### 3. 列表只保留可行动指标

作业题目行保留已提交、一次通过、最终通过和未提交，不再展示需要解释口径的“有效修改中位数”。桌面端指标聚合为同一状态带，移动端仍保持同一行；未提交学生只显示“未提交”，不重复输出两个零。

### 4. 教师成长详情使用专用紧凑视图

共享 `SingleProblemGrowthDashboard` 继续服务学生端，教师学生详情改为专用的所选提交对比：当前提交、对比提交、测试点变化、未解决问题以及真实问题变化。没有问题信号时只显示一句结果，不生成知识点、问题变化和矩阵空卡。

### 5. 提交选择器是学生证据工作区的公共状态

分类标签下方始终显示当前提交和可选提交列表；切换成长、证据或 AI 分析不改变选择。标签与面板使用稳定 ID、`aria-controls`、`aria-labelledby` 和键盘左右方向键；证据面板使用 `section`，避免页面内嵌套 `main` 地标。

### 6. 服务端显式登记正式学生详情路由

在 `FrontendForwardController` 中补充班级分析新路径的学生层级映射，并通过 MVC 测试验证返回前端入口。沿用现有显式白名单，不放宽为任意通配符，以免 API 404 被错误转发为 HTML。

## Risks / Trade-offs

- [班级入口产生多个并行请求] → 单项失败降级；浏览器验收同时检查请求数量和页面可用性，暂不引入缓存复杂度。
- [五个导航入口在更窄屏上文字拥挤] → 390px 使用四列，极窄屏切换为两列，保持最小点击高度。
- [移除教师模式通用仪表盘降低视觉炫酷感] → 以教师是否能快速比较提交变化为验收标准，学生端原仪表盘不变。
- [新提交选择器增加一行控件] → 它替代跨标签往返操作，使用紧凑状态带且只在存在提交时展示。
- [响应式覆盖受历史样式层叠影响] → 以构建后的真实页面在 1440px 与 390px 截图矩阵验收，并执行最终设计规则检测。

## Migration Plan

1. 先完成前端数据与组件改造，再补齐响应式样式和中英文文案。
2. 增加路由转发与 MVC 测试，完成前端构建和后端定向测试。
3. 使用同一份有过程证据的数据，在桌面、移动端、暗色和英文代表页面验收。
4. 若回滚，前端组件和路由映射可随同一次提交整体回退，不涉及数据迁移。
