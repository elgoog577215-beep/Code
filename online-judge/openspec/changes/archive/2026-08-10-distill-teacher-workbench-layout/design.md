## Context

教师分析的数据链已经按“班级 → 作业 → 题目 → 学生 → 提交证据”建立，但现有视图把标题说明、六项左右的指标卡、图表、问题和证据同时铺开。教师虽然能看到数据，却不能快速判断当前对象、最重要状态和下一层入口。统一教师侧栏同样保留了每个菜单的解释文字和底部脚注，进一步占用横向与纵向空间。

本次不改变后端数据合同，而是用前端工作区重新定义数据的消费顺序：导航负责分类，对象路径负责定位，状态条负责暴露关键差异，正文负责当前任务。页面不能依靠解释性段落弥补结构不清。

## Goals / Non-Goals

**Goals:**

1. 教师进入分析页后，在首屏直接看到当前对象、关键提交状态和可操作的主体内容。
2. 班级、作业、题目、学生详情分别采用符合当前任务的结构，不套用同一种卡片模板。
3. 用分区切换和主从视图替代纵向平铺，保留所有已有证据能力。
4. 保持中英文、深浅色、键盘焦点和窄屏可用。

**Non-Goals:**

1. 不修改教师分析 API、数据库、AI 诊断生成与保存逻辑。
2. 不重排学生端做题、提交和反馈流程。
3. 不在本次重写教师管理业务或作业创建表单。

## Decisions

### 1. 统一采用三层页面骨架

教师分析页使用“对象路径 → 页面栏 → 工作区”：对象路径保留下钻上下文；页面栏同一行展示标题和关键状态；工作区紧随其后。移除 hero、kicker 和说明段落。相比继续压缩原有卡片，这一结构能让层级由位置表达，而不是由文案解释。

### 2. 指标从卡片集合变为单行状态条

现有指标模型继续复用，但 UI 只以紧凑标签和数值展示。班级和作业优先展示名册、已提交、未提交、完成必做；题目优先展示已提交、一次通过、最终通过、有效修改。数据可信度、恢复样本等不会进入主状态条；如果它们只服务诊断调试，应留在开发或异常处理层，而不是教师决策层。

### 3. 按页面任务选择不同信息架构

1. 班级入口、班级页、作业页：高密度行式列表，整行进入下一层。
2. 题目页：左侧问题分类，右侧显示当前分类对应的学生；问题的涉及、常见、已解决数量在分类行内直接切换学生集合。
3. 学生详情：使用“成长轨迹 / 提交证据 / AI 分析”局部分区，同一时间只渲染当前任务的主体。成长轨迹为默认入口，提交选择在分区之间保持。
4. 教师管理和作业创建：只收敛共享侧栏及页头，业务表单本身不改结构。

### 4. 侧栏只承担分类

侧栏保留结果查看和管理工具两组，只显示图标与功能名，移除菜单说明、页脚说明和动态“教师端/管理工具”标题切换。功能含义由分组、名称和 active 状态表达。窄屏继续转为横向导航。

### 5. 用现有组件演进，不引入新依赖

`AnalyticsSummaryCards` 演进为状态条，`AnalyticsDashboard` 负责三类分析工作区，学生详情在现有页面内增加局部状态。CSS 通过明确的新语义类覆盖旧结构，删除不再使用的 hero 和卡片规则，避免并存两套视觉体系。

## Risks / Trade-offs

- [分区切换可能隐藏用户之前习惯同时查看的内容] → 默认打开最常用的成长轨迹，并在分区标签中使用清晰短名称；浏览器测试覆盖三块内容均可到达。
- [状态条在窄屏可能拥挤] → 允许横向滚动或两列换行，但不恢复独立指标卡。
- [旧浏览器测试依赖标题或说明文案] → 改为依赖路由、区域名称和真实交互，不再把解释文案当作核心契约。
- [共享侧栏变化影响管理页] → 只改变导航密度，不改变管理页路由、表单和动作。

## Migration Plan

1. 先更新教师侧栏和分析页组件，再同步中英文文案与 CSS。
2. 运行类型检查、单元测试、生产构建和教师分析浏览器回归。
3. 生成桌面、窄屏、深色截图，核对正文首屏位置、无横向溢出和学生端无结构变化。
4. 若出现回归，可按文件级回退前端变更；后端与数据无需迁移。

## Open Questions

无。问题分类口径和学生成长数据合同已在前一轮实现，本次只调整消费结构。
