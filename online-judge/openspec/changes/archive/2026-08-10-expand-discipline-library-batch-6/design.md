## Context

隔离恢复审计显示，当前生产口径为 737 个启用知识节点、586 个启用叶子、140 个能力点、381 个易错点、138 个提升点和 34 个应用场景。454 个叶子仍使用“细颗粒知识点”占位描述，其中 401 个没有精确主能力点。上一批已经把正式能力无提升路径降为 0，本批不能继续给既有能力机械叠加同义提升点，而应在未形成诊断闭环的叶子上新增完整主题包。

正式内容由 PostgreSQL 与 Flyway 管理，V1–V10 已发布且不得修改。运行时 seed 已退出主链路；规范化能力、易错、提升表是主结构，平铺条目和 legacy mapping 仅承担兼容读取。课堂与竞赛必须复用同一知识点和能力点，应用场景只为 AI 与教师提供任务和验收语境，不能充当当前提交证据。

## Goals / Non-Goals

**Goals:**

- 在 ALGO、BASIC、CONTEST、DS、ENG、MATH 六个领域各选择 8 个仍为模板且无精确主能力的叶子，形成 48 个高质量主题包。
- 每包同时交付精修知识文本、正式能力、3 个不同错误行为、1 个迁移练习和 1 组课堂—竞赛场景，避免孤立标签。
- 新增 336 条标准层内容，使核心标准层记录从 693 增至至少 1029，并使五类有效文本总量相对生产 V10 基线增长至少 40%。
- 用结构、文本、引用、兼容和幂等门禁证明增量可被导航和治理链路真实使用。

**Non-Goals:**

- 不为达到行数或记录数继续创建同义能力、抽象错因或换词场景。
- 不新增知识节点，不改变稳定 code、上层目录和统一高中/竞赛知识树边界。
- 不修改 AI 推理协议，不把标准库变成规则引擎，不把应用场景当作命中证据。
- 不根据当前有限诊断样本宣称错误频率、学习效果或竞赛成绩提升。

## Decisions

### 1. 以 48 个完整主题包作为唯一增长单位

每个主题包固定为 `1 个既有知识点精修 + 1 个新能力 + 3 个新易错点 + 1 个新提升点 + 2 个新场景`。三类易错分别覆盖语义/对象误读、边界/状态破坏和验证/复测遗漏，必须有不同触发条件、症状与修复动作。替代方案是只批量新增错因或提升点，但会再次造成归属松散和导航密度失衡，因此不采用。

### 2. 六领域等额，不按历史条目数量继续倾斜

ALGO 与 BASIC 的剩余债务更大，但 ENG、MATH、DS、CONTEST 的精确诊断密度更低。本批各领域固定 8 包，优先保证横向完整；下一批再依据真实教师校正与命中数据调整权重。等额只是批次范围，不允许用低价值主题补足名额，候选必须同时满足“模板叶子、无精确主能力、能够写出三个不同可观察错因”。

### 3. V11 使用批次临时目录驱动规范化写入

迁移先声明 48 个主题目录和每包的完整内容，再由同一批次数据写入知识点、能力、易错、提升、平铺快照、legacy mapping 与应用场景。这样可在事务内比较六层 code 集合和归属，避免复制 SQL 时发生三表漂移。临时目录只存在于迁移事务，不是运行时 seed，也不会进入生产表。

### 4. 质量目标同时看记录数与有效文本体积

记录数只证明结构增长，不证明内容价值。V11 同时计算知识描述/目标/典型问题、能力目标、错因解释/症状/修复、提升练习/收益/教师验收和场景任务/证据/成功标准的字符总量；正式基线按同口径固化，迁移后至少增长 40%。文本门禁还检查禁用短语、字段最低长度、同锚点同名、重复三元组和场景任务重复，避免用空字段或改写模板达到阈值。第一轮完整内容实测新增 110,954 个有效字符，约为生产 V10 基线的 45%，因此不再为追求更高比例追加同义表达。

### 5. 应用场景继续成对但不扩张 AI 权限

每个新能力拥有 1 个课堂场景和 1 个竞赛场景，并用 `transfer_pair_code` 配对。课堂场景强调学生产物、教师观察和形成性检查；竞赛场景强调约束、复杂度、边界与赛后复盘。场景 code 不是合法诊断 ID，`common_failure` 不是当前提交证据，现有题目、代码、判题事实和 evidenceRefs 始终优先。

## Risks / Trade-offs

- [48 个主题仍无法覆盖全部 454 个模板叶子] → 本批优先形成可复用质量样板和显著内容增量；剩余债务继续保留为显式指标，不用低质量自动补齐。
- [批次 SQL 体积较大且人工内容容易错配] → 使用单一主题目录派生全部规范表，并加入事务内计数、code 集合、归属、字段长度和重复检测。
- [等额领域分配可能偏离未来真实高频] → 明确本批是结构与学科范围驱动，不宣称行为频率；真实 cohort 到达后再按命中、PARTIAL/MISS 和教师校正重排。
- [场景文本可能模板化] → 每个场景必须包含主题特定任务产物、观察证据、常见失败、约束与成功标准；相同任务或成功标准重复将阻断。
- [已发布迁移不可逆] → 先在生产备份的隔离恢复库验证，正式发布前备份并保留旧镜像；失败时停止新应用并恢复备份，不修改 V11 校验值。

## Migration Plan

1. 固化生产 V10 的内容计数、有效文本体积、模板债务和核心业务表计数。
2. 新增 V11，静态检查只更新 48 个既有模板叶子并新增批次 6 标准内容。
3. 在隔离 PostgreSQL 执行 V11、重复执行原始 SQL、运行学科质量门禁与六领域代表性导航。
4. 运行 V1→V11 空库迁移、显式 baseline、重复启动、Schema 漂移阻断、专项与完整后端测试。
5. 归档 OpenSpec、提交并 fetch 远端；确认分支关系后推送。
6. 若进入生产发布，先生成可校验备份，再核对 Flyway V11、业务表计数、内容门禁和应用健康。

## Open Questions

无。若 48 个候选中任一主题无法形成三个不同可观察错因，则从同领域候选清单替换，不降低内容门禁。
