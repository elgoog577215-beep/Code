## Context

当前教师分析已经完成“班级 → 作业 → 题目 → 学生 → 提交”的产品收敛，移动端也已保证五个入口完整可达。本次基于 1440×1000 的真实页面基线，只处理桌面结构：浅层页面有大量无组织空白，侧栏像单独卡片，标题与状态横跨正文两端；深层学生页面虽然信息完整，但标签、提交选择、时间线和证据内容没有形成一个连续工作区。

## Goals / Non-Goals

**Goals:**

- 让教师在五秒内看清当前对象、关键状态、下一层入口和证据。
- 用稳定列、进度线和对齐关系提升班级、作业、题目的比较效率。
- 让学生详情在桌面上形成连续的“分类 + 当前提交 + 证据”工作区。
- 在不增加说明文案、卡片和装饰性统计的前提下提高信息密度和视觉完成度。
- 保持中文、英文、深色、键盘以及 390px 移动端可用。

**Non-Goals:**

- 不增加教师分析维度、图表或后端统计。
- 不改变问题生命周期、分子分母、AI 版本和证据合同。
- 不重排学生端页面。
- 不把桌面端做成仪表盘卡片墙。

## Decisions

### 1. 以连续工作台代替悬浮侧栏卡

桌面端侧栏去掉独立圆角卡轮廓，改为从主内容起点连续延伸的垂直轨道，以右边界分隔导航和正文。侧栏保持 sticky，正文保留充足但稳定的左右边界。相比扩大卡片或增加阴影，这能更直接表达“导航控制同一工作区”。

### 2. 对象栏采用标题、状态、操作三段式紧凑结构

页面路径保持在对象栏上方；标题靠左，指标紧随其后，主操作在最右。指标之间继续使用细分隔，不新增指标卡。这样既保留横向效率，又避免标题和数字失联。

### 3. 浅层列表增加提交进度，不增加统计

班级、作业和题目行复用已有分子分母计算 CSS 进度线。身份信息占主列，进度和同口径指标形成固定列，箭头只作为最末下钻提示。进度只是现有事实的视觉投影，不引入新口径。

### 4. 题目页和学生页采用不同桌面密度

题目页优先横向比较，阶段条和学生列表占满工作列；学生页优先证据阅读，将分类标签和提交选择合并为 sticky-ready 的单一控制栏，成长时间线、提交对比和证据正文保持更适合材料的最大宽度。两者共享视觉语言，但不强迫使用同一种组件形状。

### 5. 时间格式由当前 locale 显式驱动

成长时间线不再直接调用浏览器默认 `toLocaleString()`，而由 i18n locale 传入统一格式化函数。中文使用 `zh-CN`，英文使用 `en-US`，并采用年、月、日、时、分的紧凑显示，避免运行环境决定结果。

## Risks / Trade-offs

- [宽屏优化可能影响 1180px 临界布局] → 桌面增强限定在 `min-width: 1181px`，现有 1180px、900px、760px 断点继续负责降级。
- [进度线可能被误解为新的评价分数] → 只在明确标注“已提交”且已有分子分母的行内使用，不改变数字、不使用百分制文案。
- [侧栏去卡后深色边界不清] → 复用现有 `--line`、`--surface` 和品牌 active 状态，在深色截图中单独验收。
- [学生时间线格式修改影响学生端] → `GrowthTimeline` 根据当前 locale 格式化，但不改结构；回归学生端代表页。

## Migration Plan

1. 先改桌面 CSS 和必要组件结构，保留所有现有移动断点。
2. 同步中英文无障碍和进度文案。
3. 运行前端生产构建、OpenSpec 校验和设计机械检测。
4. 对 1440px 五层分析、英文、深色及 390px 教师端与学生端保护页做真实截图验收。
5. 若出现回归，可按本次集中 CSS、组件和本地化改动整体回退，不涉及数据迁移。
